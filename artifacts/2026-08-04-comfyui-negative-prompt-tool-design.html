ComfyUI Negative Prompt Auto-Generation Tool

✓ Approved Open WebUI Tool 2026-08-04 compose/comfyui/tools/image_negative_prompt_gen.py

Problem & Goal

Problem: Open WebUI's built-in ComfyUI integration only populates the positive prompt (node 6). Node 7 (negative) stays hardcoded at the workflow default — a generic artefact list not tailored to the subject being drawn.
Goal: Replace the generic negative prompt with one automatically generated from the positive prompt using the same LLM already in VRAM — no model swap, no new services.

Architecture

An Open WebUI Tool (Python plugin). Gemma4 calls the tool when the user requests an image. Negative prompt generation and ComfyUI submission both happen inside the tool.

Data Flow

User: "draw an anime girl reading in a rainy library"
↓
Gemma4 → calls generate_anime_image(positive_prompt="...")
↓
Step 1 GET /api/ps → discover loaded model name
Step 2 POST /api/generate to Ollama
            system: <negative_prompt_system valve>
            prompt: <positive_prompt>
            stream: false
            → "lowres, bad anatomy, extra fingers, blurry, watermark…"
Step 3 POST /prompt to ComfyUI
            node 6 ← positive_prompt
            node 7 ← generated negative_prompt
Step 4 Poll /history → fetch image bytes
↓
HTMLResponse: inline image + collapsible details (both prompts, seed, size, steps)
No model eviction. Gemma4 is already loaded from the chat turn that triggered the tool. The internal Ollama call hits the same model — no swap, ~3–8 s added latency before ComfyUI starts.

Tool Signature

negative_prompt is not a parameter. The LLM never supplies it — it is generated inside the tool from positive_prompt.

Default negative_prompt_system

You are a Stable Diffusion prompt engineer. Given a positive image prompt,
output ONLY a comma-separated negative prompt with no explanation or preamble.
Exclude: anatomy defects (bad anatomy, bad hands, extra fingers, missing fingers,
fused limbs), quality defects (lowres, blurry, jpeg artifacts, noise, worst quality),
and unwanted content (text, watermark, signature, logo, username).
Also exclude traits that contradict the style, mood, or subject in the positive prompt.
Never negate a trait that was explicitly requested.

Key Internal Methods

_get_loaded_model

async def _get_loaded_model(self, client: httpx.AsyncClient) -> str:
    r = await client.get(f"{self.valves.ollama_url}/api/ps")
    models = r.json().get("models", [])
    if models:
        return models[0]["name"]
    if self.valves.ollama_model:
        return self.valves.ollama_model
    raise RuntimeError("No model loaded in Ollama and ollama_model valve is not set.")

_generate_negative_prompt

async def _generate_negative_prompt(self, client: httpx.AsyncClient, positive_prompt: str) -> str:
    model = await self._get_loaded_model(client)
    r = await client.post(
        f"{self.valves.ollama_url}/api/generate",
        json={
            "model": model,
            "system": self.valves.negative_prompt_system,
            "prompt": positive_prompt,
            "stream": False,
        },
        timeout=httpx.Timeout(30.0),
    )
    r.raise_for_status()
    return r.json()["response"].strip()

Error Handling

FailureBehaviour
Ollama unreachable / /api/ps failsEmit warning → use fallback → continue to ComfyUI
Ollama returns empty / malformed responseEmit warning → use fallback → continue to ComfyUI
ComfyUI unreachableEmit error → raise — no image returned
ComfyUI rejects workflowEmit error → raise — no image returned
Image generation is never blocked by a failure in the negative prompt step. The fallback produces the same result as today's hardcoded node 7.

Deployment

  • Update compose/comfyui/tools/image_negative_prompt_gen.py with the final implementation.
  • In Open WebUI admin UI: Workspace → Tools → Create new tool → paste file content.
  • Set ollama_url and comfyui_url valves via the tool settings panel.
  • In Open WebUI admin UI: Workspace → Models → Gemma4 → enable this tool.
  • Test: ask Gemma4 to generate an image. Confirm both prompts appear in the collapsible "Generation details" section.
No Docker or compose changes required. The existing built-in image generation (.cfg files, prompt_node = 6) is unaffected — it is a separate code path used by the native image button.

Out of Scope

  • Replacing the built-in image generation integration
  • Supporting multiple simultaneous image requests
  • Negative prompt caching or reuse across requests
  • Supporting workflows with different node layouts
